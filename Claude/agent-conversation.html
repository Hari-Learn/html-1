Agent State Management

Page 29 | Maintaining context and progress

1. Agent State

Information about what the agent is doing and what has already happened.

Example: Customer verified, order retrieved, refund pending.

2. Conversation History

Previous messages exchanged between customer and agent.

Helps Claude understand earlier questions and responses.

3. Short-Term Memory

Information needed during the current task or conversation.

Example: Current order ID and refund status.

4. Long-Term Memory

Information retained across separate conversations when the application supports it.

Example: A customer's preferred communication language.

5. Checkpointing

Saving the agent's progress at important stages.

If execution stops, the system may resume from a saved checkpoint.

6. Context Compaction

Reducing lengthy conversation history into a shorter useful representation.

Preserve important decisions, facts and pending tasks.

7. State vs Memory

State describes the current execution status.

Memory stores useful information for future reasoning.

They are related, but not identical.

8. State Persistence

Storing state outside temporary execution memory.

Useful when an agent needs to survive restarts or continue later.

Example Workflow

Customer asks for refund → Verify customer → Retrieve order → Save progress → Process refund → Update state → Respond.
