MCP Tasks

How to manage operations that take a long time.

1. Understand with an analogy

Imagine ordering a custom-made cupboard.

  • You place the order.
  • The shop gives you an order number.
  • You check the order status later.
  • When it is ready, you collect the cupboard.

MCP Tasks work similarly: receive a task ID first, retrieve the result later.

2. Why do we need Tasks?

A normal tool call may block while a long operation runs.

Tasks are useful for:

  • Large document processing.
  • Long-running data analysis.
  • Cloud deployment jobs.
  • Batch processing.
  • Workflows waiting for human approval.

3. Important Task methods

MethodPurpose
tasks/getCheck task status and retrieve its details.
tasks/updateProvide requested input to a task.
tasks/cancelRequest cancellation of a task.

These belong to the MCP Tasks extension.

4. Know the five task statuses

working

Task is still running.

input_required

Server needs input before continuing.

completed

Task finished and has a result.

failed

Task execution failed.

cancelled

Task reached the cancelled state.

Remember: completed, failed and cancelled are terminal statuses.

5. Example workflow

Client calls a long-running tool
↓
Server returns task ID
↓
Client checks using tasks/get
↓
Still working? Check again later.
↓
Completed? Retrieve final result.

6. Rare exam concept: input_required

Imagine Claude starts a production deployment. The server needs manager approval.

The task changes to input_required.

The client supplies the requested response using tasks/update. The task can then continue.

Important: input_required does not mean the task failed.

7. Exam traps

  • Do not treat a task ID as the final result.
  • Do not repeatedly poll faster than the suggested poll interval.
  • Store task IDs if the workflow must resume after a restart.
  • Do not assume every tool call automatically becomes a task.
  • Task cancellation is not guaranteed to stop work immediately.

8. Quick exam question

A deployment tool takes 20 minutes. The MCP server returns a task ID and status "working". What should the client do?

Reveal answer

Use tasks/get to check the task later, respecting the suggested polling interval. Retrieve the final result when completed.
