API Reliability & Output

Structured output, streaming and error handling.

1. Structured Output

Structured output helps applications consume responses in a predictable format such as JSON.

{
  "category": "billing",
  "priority": "high",
  "summary": "Duplicate charge"
}

Always validate the structure and business meaning before using the data.

2. Streaming

Streaming sends response pieces as they are generated instead of waiting for the complete response.

Chunk 1
Chunk 2
Chunk 3

Benefit: Faster perceived response in interactive applications.

3. Exponential Backoff

When temporary errors occur, retry after progressively longer delays.

1s → 2s → 4s → 8s

Add random jitter and a maximum retry limit.

Respect Retry-After guidance when provided. Avoid blindly retrying permanent errors.

4. Rate Limits

Rate limits control how many requests an application can make within a given period.

  • Monitor request volume.
  • Use bounded retries.
  • Respect rate-limit headers.
  • Control concurrent requests.

Exam Scenario

Your application receives occasional HTTP 429 responses. What should you do?

Reveal Answer

Use bounded exponential backoff with jitter and respect retry guidance.

Key idea: Validate outputs, stream for responsiveness and retry temporary failures intelligently.
