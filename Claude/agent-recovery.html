Tool Errors & Recovery

How agents handle failures without creating bigger problems

Types of Errors

  • Timeout — response took too long
  • Rate limit — too many requests
  • Validation error — wrong input
  • Permission error — not authorized
  • Server error — backend problem

Retry vs Don't Retry

Retry: temporary network issue, timeout, transient server failure.

Don't blindly retry: invalid input, denied permission, policy violation.

Exponential Backoff

Increase waiting time after each retry.

Example: 1 sec → 2 sec → 4 sec → 8 sec.

Add jitter (random delay) to reduce simultaneous retries.

Safe Recovery

  • Check whether action already succeeded
  • Use idempotency keys for sensitive operations
  • Limit retry attempts
  • Provide fallback or human escalation
  • Communicate honestly with the user

Exam Insight

A timeout does not always mean the action failed. Verify the outcome before repeating actions like refunds, payments or bookings.
