MCP Lifecycle & Capabilities

How an MCP client and server establish communication

1. Initialization

The client connects to the MCP server and sends initialization information.

Both sides establish protocol compatibility and exchange capabilities.

2. Capability Negotiation

Client and server advertise the features they support.

  • Tools
  • Resources
  • Prompts
  • Sampling
  • Other supported capabilities

3. Initialized Notification

After initialization, the client sends an initialized notification.

Normal operation can then begin.

4. Normal Operation

The client and server exchange requests, responses and notifications.

Example: Client requests a tool; server returns its result.

Why Capabilities Matter

A client should not assume every server supports every feature.

It should use the capabilities actually advertised by the connected server.

Common Mistake

A server supports tools but not sampling.

The client must not assume it can use sampling just because it supports MCP.

Exam Insight

When an MCP feature is unavailable, check initialization and advertised capabilities before assuming the server is broken.
