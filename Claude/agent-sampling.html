MCP Sampling

How MCP servers request model-generated results

What Is Sampling?

Sampling allows an MCP server to request an LLM completion through the connected client.

The client controls the model interaction rather than the server directly accessing the model.

Normal Tool Call vs Sampling

Tool call: The model asks a server to perform an operation.

Sampling: The server asks the client to obtain model-generated content.

Sampling Flow

MCP Server → Client → Model → Client → MCP Server

The client receives the request, applies its policies and decides how to handle it.

Example

A research MCP server collects several documents.

It requests a model-generated summary through the client.

The client processes the request and returns the generated result.

Security & Control

  • Client can apply model-use policies
  • Client can control model selection
  • Requests and results need validation
  • Untrusted server instructions must not override trusted policies

Important Limitation

Sampling is an optional MCP capability.

Both the relevant client and server must support the required functionality.

It does not mean every MCP server can freely call Claude.

Exam Insight

If an MCP server needs an LLM-generated result, consider sampling. Remember that the client mediates the request and retains control over model access.
