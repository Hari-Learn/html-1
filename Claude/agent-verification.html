Verification workflow

20 steps to verify an agent

Work through each stage and record evidence rather than relying only on the agent's final response.

01

Define the agent's objective

Write down exactly what the Claude agent is expected to accomplish.

02

Define success criteria

Specify measurable conditions that determine whether the task succeeded.

03

Identify allowed tools

Document which tools, APIs, files, or external resources the agent may use.

04

Prepare a controlled test

Create a repeatable input so the same agent behavior can be evaluated consistently.

05

Send the initial task

Give Claude the task without adding hidden assumptions after execution begins.

06

Check instruction following

Verify that the agent follows the stated requirements and constraints.

07

Inspect tool selection

Check whether the agent selects appropriate tools for each operation.

08

Verify tool inputs

Confirm that arguments sent to tools are accurate, complete, and within scope.

09

Verify tool outputs

Check that returned information is interpreted correctly rather than assumed.

10

Check intermediate reasoning

Review observable decisions and intermediate actions for consistency with the task.

11

Test missing information

Provide incomplete inputs and check whether the agent asks for clarification when needed.

12

Test invalid inputs

Introduce malformed or unsupported inputs and verify graceful handling.

13

Test boundary conditions

Evaluate unusual but valid cases near the limits of the task requirements.

14

Check safety constraints

Verify that the agent respects permissions, access boundaries, and defined restrictions.

15

Check external claims

Require important claims to be supported by available evidence or clearly marked as uncertain.

16

Repeat the same test

Run the scenario multiple times to identify inconsistent behavior.

17

Run adversarial cases

Try misleading instructions, conflicting requirements, and unexpected task sequences.

18

Compare results against criteria

Match the observed behavior against the success criteria defined at the beginning.

19

Record evidence

Capture relevant inputs, outputs, tool calls, failures, and verification results.

20

Mark verification status

Record whether the agent passed, failed, or requires another verification cycle.

Final checklist

Verification evidence

✓
Objective is explicit

The agent's expected behavior is clearly documented.

✓
Tools are controlled

Tool access and permitted operations are known.

✓
Outputs are testable

Results can be compared against defined criteria.

✓
Failures are recorded

Unexpected behavior is documented instead of ignored.

✓
Edge cases are tested

The agent has been tested beyond the simplest happy path.

✓
Evidence is reproducible

Another reviewer can repeat the verification process.

Verification complete

Evidence-backed agent verification

A verified workflow should document what was tested, what happened, which tools were used, and how the result matched the expected criteria.
