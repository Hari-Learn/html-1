Agent Reliability

Page 28 | Building dependable agents

1. Idempotency

An operation is idempotent when repeating it produces the same final result as doing it once.

Example:

Refund request sent twice with the same idempotency key should not create two refunds.

2. Idempotency Key

A unique identifier attached to an operation.

The backend uses it to recognize duplicate requests.

Example: refund-ORD123-001

3. Timeout

The agent waits for a tool response, but the response does not arrive within the allowed time.

Important: Timeout does not always mean the operation failed.

4. Retry Strategy

Retry temporary failures using controlled attempts.

Exponential backoff increases the waiting time between retries.

Example: 1s → 2s → 4s → 8s.

5. Circuit Breaker

Temporarily stops calls to a failing service.

Prevents repeated requests from overwhelming an unhealthy backend.

States: Closed, Open, Half-open.

6. Graceful Degradation

When one service fails, the agent still provides whatever useful service is safely possible.

Example: Explain refund eligibility even if refund processing is temporarily unavailable.

Remember

Retry handles temporary failure.

Idempotency prevents duplicate actions.

Circuit breaker protects failing services.

Graceful degradation preserves useful functionality.
