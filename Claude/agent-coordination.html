Multi-Agent Coordination

Page 33 | Delegation and orchestration

1. Multi-Agent System

Multiple agents work together to solve a larger task.

Each agent may have a specific role, tools or responsibilities.

2. Orchestrator

The main agent coordinates the workflow.

It assigns work, collects results and decides what happens next.

3. Subagent

A delegated agent handles a specific task.

Example: A research subagent finds relevant information while the main agent handles the final response.

4. Parallel Execution

Independent tasks can run at the same time.

Example: Check order history and review refund policy simultaneously.

May reduce total latency.

5. Sequential Execution

Tasks run in order when one depends on another.

Example: Verify customer → retrieve order → calculate refund → process refund.

6. Delegation Boundaries

Define what the subagent can do, what information it receives and what it must return.

Avoid giving every agent unrestricted access to every tool.

7. Coordination Overhead

More agents can increase complexity, token usage, latency and failure points.

Use multiple agents only when delegation provides real value.

8. Result Validation

The orchestrator should verify delegated results before using them.

Subagents may return incomplete, inaccurate or conflicting information.

Exam Scenario

A travel agent must compare 10 hotels, 10 flights and weather at the destination.

Best design: Delegate independent research tasks in parallel, then let the orchestrator compare and combine results before making the final recommendation.

Quick Revision

  • Orchestrator = coordinates.
  • Subagent = performs delegated work.
  • Parallel = independent tasks at the same time.
  • Sequential = dependent tasks in order.
  • Delegation = clear task and boundaries.
  • More agents do not always mean better results.
