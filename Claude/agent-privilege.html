Tool Permissions & Least Privilege

Page 31 | Agent Security

1. Least Privilege

Give an agent only the permissions it needs to perform its task.

Example: A shipping agent can check tracking but cannot issue refunds.

2. Read vs Write Tools

Read tools retrieve information. Write tools change something in the real world.

Example: get_order is read. cancel_order is write.

3. Tool Authorization

Verify that the agent and user are allowed to perform an action.

Never rely only on Claude's decision to enforce authorization.

4. Human Approval

Require human confirmation before sensitive or high-impact actions.

Example: Large refund, account closure or unusual payment action.

5. Scope Restrictions

Restrict tools to specific accounts, resources or data.

Example: Agent can access only the current customer's orders.

6. Permission Separation

Separate responsibilities across tools or agents.

One component retrieves data; another authorized component performs sensitive actions.

Exam Scenario

A customer-support agent can retrieve customer records and issue refunds. A malicious customer asks it to refund another person's order.

Best protection: Enforce customer ownership and refund authorization in the backend, not just in the prompt.

Quick Revision

  • Least privilege = minimum necessary access.
  • Read tools = retrieve information.
  • Write tools = change information or perform actions.
  • Authorization = verify permission.
  • Human approval = extra oversight for sensitive actions.
