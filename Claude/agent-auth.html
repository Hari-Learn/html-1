Agent Security

Identity, permissions and protecting sensitive actions

Authentication

Authentication answers:

"Who are you?"

Verifies the identity of the user or system.

Example: Login using password or OTP.

Authorization

Authorization answers:

"What are you allowed to do?"

Controls access to resources and actions.

Example: User can view an order but cannot issue refunds.

Least Privilege

Give an agent only the permissions needed for its task.

  • Read-only access when possible
  • Separate read and write tools
  • Restrict sensitive operations
  • Avoid unrestricted database access

Secrets Management

Protect API keys, tokens and credentials.

  • Never place secrets in prompts
  • Don't expose credentials in logs
  • Use secure server-side storage
  • Rotate compromised credentials

Sensitive Actions

Extra safeguards for actions such as:

  • Money transfers
  • Refunds
  • Deleting records
  • Changing account ownership

Use verification, permission checks and approval when required.

Defense in Depth

Never depend on a single security layer.

Combine permissions, input validation, policy checks, monitoring and confirmation.

Exam Insight

If an agent has too much access, reduce permissions at the tool/backend level. Don't rely only on telling Claude to behave safely.
