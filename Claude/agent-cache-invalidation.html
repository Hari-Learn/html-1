Claude API: Cache Invalidation

Rare Topic 24 | CCAO-F Notes

1. What is invalidation?

Cache invalidation means an existing cached prefix can no longer be reused because the relevant content or configuration changed.

Claude may need to create a new cache entry.

2. Understand the hierarchy

Tools
↓
System Prompt
↓
Messages

The cache is based on matching prefixes in this order.

3. What changes invalidate?

Change Affected cache
Change tool definitions Tools + System + Messages
Change system prompt System + Messages
Change tool choice Messages
Add or remove images Messages
Change thinking settings Messages; sometimes earlier cache levels too, depending on model

4. Example: Tool change

Your application has 10 tool definitions. You add an 11th tool.

The tool-definition prefix has changed, so the existing cache based on that prefix cannot be reused.

5. Example: Tool choice

Your tool definitions and system prompt remain the same, but you change the tool_choice setting.

The tools and system cache can remain valid; the messages cache is affected.

6. How to reduce unnecessary invalidation

  • Keep tool definitions stable.
  • Keep frequently reused system instructions unchanged.
  • Place stable content before changing content.
  • Avoid changing configuration unnecessarily between requests.
  • Check model-specific caching behaviour.

ELI10 Example: A school notebook

Think of a notebook with three parts: school rules, teacher instructions and daily lessons.

If you change the school rules, later parts may need to be rewritten. If you change only today's lesson, the earlier pages can remain unchanged.

Exam Scenario

A developer changes only the tool_choice parameter. The tool definitions and system prompt stay unchanged. Which cache level is affected?

Reveal answer

The messages cache. The tools and system cache can remain valid.
