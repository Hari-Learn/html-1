Agents, MCP & Tool Orchestration

Understanding how Claude interacts with external systems.

1. Agentic Loop

1. Plan
2. Act
3. Observe
4. Repeat / Stop

An agent selects actions based on previous results until it reaches its goal or a stopping condition.

2. MCP Architecture

Model Context Protocol connects AI applications with external tools and context providers.

Host — AI application
↓
Client — Manages connection
↓
MCP Server — Exposes capabilities

Exam trap: MCP is a protocol, not a model or database.

3. MCP: Tools vs Resources vs Prompts

Tools

Actions: lookup_order(), create_ticket().

Resources

Data/context: policy documents, files.

Prompts

Reusable prompt templates or workflows.

4. State vs Context vs Memory

  • Context: Information available in the current request.
  • State: Current workflow status.
  • Memory: Information retained for future interactions by the application.

Exam trap: Claude API does not automatically remember every previous request.

5. Human-in-the-Loop (HITL)

Human review or approval at important decision points.

Lower risk

Search policy, retrieve order status, draft reply.

Higher risk

Issue refund, delete data, change ownership.

Approval should be required according to the action's risk and organizational policy.

6. Autonomy & Stop Conditions

  • Allowed tools and permissions.
  • Maximum number of steps.
  • Timeout and spending limits.
  • Human approval thresholds.
  • Escalation rules.
  • Clear success and stopping conditions.
