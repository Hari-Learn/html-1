Thread-Per-Request

A concurrency model where a separate thread is created to handle each incoming client request.

How It Works

  • Client sends a request.
  • Server creates a new thread.
  • The thread processes the request.
  • The thread ends after completing the task.

Advantages

  • Simple to implement.
  • Handles multiple clients simultaneously.
  • Improves responsiveness.
  • Easy to understand and debug.

Disadvantages

  • High memory usage for many threads.
  • Thread creation takes time.
  • Too many threads reduce performance.
  • Not suitable for very high-traffic servers.

Summary

The Thread-Per-Request model assigns one thread to each client request. It is easy to develop and provides good concurrency, but creating a new thread for every request can become expensive when the number of clients is very large.
