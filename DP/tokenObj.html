Token Bucket Design Pattern

The Token Bucket pattern is a rate-limiting algorithm used to control how frequently requests or operations can be executed. A bucket stores tokens that are added at a fixed rate. Every request consumes one token. If no tokens are available, the request is delayed or rejected.

How It Works

  1. Create a bucket with a maximum capacity.
  2. Add tokens continuously at a fixed rate.
  3. Each incoming request consumes one token.
  4. If a token exists, the request is processed.
  5. If the bucket is empty, reject or wait.

Flow

Client → Token Bucket → Available Token? → Process Request → Response

Java Example


class TokenBucket {

    int tokens = 5;

    boolean allowRequest() {
        if(tokens > 0){
            tokens--;
            return true;
        }
        return false;
    }
}

Advantages

  • Simple rate limiting.
  • Allows burst traffic.
  • Prevents server overload.
  • Easy to implement.
  • Improves system stability.

Disadvantages

  • Requires periodic token refill.
  • Needs synchronization in multithreading.
  • Choosing bucket size can be difficult.

Common Use Cases

  • API Rate Limiting
  • Network Traffic Shaping
  • Cloud Services
  • Gateway Request Control
  • Distributed Systems
Key Idea: Tokens represent permission to execute work.
