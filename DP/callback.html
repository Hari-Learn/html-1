Callback Pattern

Behavioral Design Pattern
Execute user-provided code later.

What is a Callback?

A Callback is a function that is passed to another function so it can be executed at a later time.

Instead of deciding what should happen, a class lets the caller provide the behavior.

Goal: Execute user-provided code when an event or task occurs.

How It Works

Application
      │
      ▼
Register Callback
      │
      ▼
Program stores callback
      │
      ▼
Event Happens
      │
      ▼
Execute Callback

Main Components

👤 Caller

Registers the callback function.

⚙️ Callback Function

User-provided code that will execute later.

📦 Event Source

Stores the callback until an event occurs.

🚀 Event

Triggers execution of the registered callback.

Real-World Uses

  • Button click handlers in GUI applications.
  • Timers that execute code after a delay.
  • Asynchronous networking operations.
  • File download completion notifications.
  • Game event handling.

Advantages

✅ Flexible

Different behaviors can be supplied without changing the class.

✅ Reusable

One component can work with many callback functions.

✅ Event Driven

Ideal for handling user interactions and asynchronous tasks.

✅ Decoupled

The event source doesn't need to know what the callback does.

Disadvantages

  • Can make program flow harder to follow.
  • Nested callbacks may reduce readability ("callback hell").
  • Lifetime management must be handled carefully.
  • Debugging asynchronous callbacks can be challenging.

ELI10 (Explain Like I'm 10)

Imagine you ask your friend:

"When the pizza delivery arrives, call me immediately!"

Your friend doesn't call you right away. They wait until the pizza actually arrives.

  • 🍕 Pizza arrives = Event
  • 👤 Friend = Program
  • 📞 Calling you = Callback
Key Idea:
You give the program a function now, but it executes that function later when something interesting happens.
