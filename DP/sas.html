Scheduler Agent Supervisor (SAS) Pattern

The Scheduler Agent Supervisor (SAS) pattern separates scheduling, task execution, and supervision into independent components. A scheduler assigns work, agents execute tasks, and supervisors monitor execution, detect failures, retry jobs, and ensure the system continues operating reliably.

What is the Scheduler Agent Supervisor Pattern?

In distributed systems, background jobs are rarely executed directly by the application. Instead, a dedicated scheduler creates jobs, worker agents perform the work, and supervisors continuously monitor job health. If an agent crashes or becomes unresponsive, the supervisor can restart, reassign, or retry the job automatically.

Core Idea: Separate scheduling, execution, and monitoring into independent responsibilities.

Problem

  • Long-running jobs may fail unexpectedly.
  • Worker crashes leave tasks incomplete.
  • Applications cannot continuously monitor background jobs.
  • Retry logic becomes duplicated.
  • Scheduling and execution become tightly coupled.

Solution

  • Scheduler creates and assigns jobs.
  • Agents execute assigned work.
  • Supervisor monitors every running task.
  • Automatic retries after failures.
  • Supports scalable distributed execution.

Java Example 

class Scheduler {

    public void schedule(Job job) {
        queue.add(job);
    }

}

class WorkerAgent {

    public void execute(Job job) {

        try {

            job.run();

        } catch(Exception ex) {

            Supervisor.notifyFailure(job);

        }

    }

}

class Supervisor {

    public static void notifyFailure(Job job) {

        System.out.println("Retrying " + job.getName());

        queue.add(job);

    }

}

Component Responsibilities

Component Responsibility
Scheduler Creates jobs based on time, events, or requests.
Queue Stores pending work.
Worker Agent Executes assigned jobs.
Supervisor Detects failures, retries, monitors health.
Monitoring System Generates alerts and metrics.

Advantages

  • High fault tolerance.
  • Automatic retry mechanisms.
  • Easy horizontal scaling.
  • Clear separation of responsibilities.
  • Centralized monitoring.
  • Supports long-running workflows.
  • Improves reliability.

Disadvantages

  • More infrastructure components.
  • Higher operational complexity.
  • Requires reliable messaging.
  • Supervisor itself may need redundancy.
  • Retry policies must be carefully designed.

Best Practices

  • Keep scheduler stateless whenever possible.
  • Make jobs idempotent for safe retries.
  • Implement heartbeat monitoring for workers.
  • Use exponential backoff for retries.
  • Persist job state in durable storage.
  • Track metrics for execution time and failures.
  • Dead-letter permanently failed jobs.
  • Prevent duplicate execution using distributed locks.

Scheduler Agent Supervisor Design Pattern

The Scheduler Agent Supervisor pattern improves reliability in distributed systems by separating job scheduling, execution, and supervision. This architecture enables automatic recovery, scalable background processing, and resilient workflow execution for enterprise applications.
