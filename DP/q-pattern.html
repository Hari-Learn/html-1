Here’s a polished single-page Tailwind HTML example, under 150 lines, explaining the **Question Pattern** and how it separates information retrieval from actions and assertions. ``` Question Pattern
Test Automation Pattern

Question Pattern

Retrieves information from the application so assertions can be separated from actions. It is commonly used with the Screenplay Pattern.

👤

Actor

Performs tasks and interacts with the application.

❓

Question

Retrieves a value or state from the application.

✓

Assertion

Verifies the answer without mixing validation with actions.

Screenplay Example

Question<String> welcomeMessage() {
  return Text.of(WELCOME_MESSAGE);
}

actor.attemptsTo(
  Login.withCredentials("alice", "secret")
);

actor.should(
  seeThat(welcomeMessage(), equalTo("Welcome, Alice!"))
);

Key Benefits

🧩

Separation

Keeps actions and assertions independent.

♻️

Reusable

Questions can be reused across multiple scenarios.

📖

Readable

Tests read naturally as behavior-focused statements.

🛠️

Maintainable

UI retrieval logic stays isolated from test expectations.

Pattern in one line

Actor performs an action → Question retrieves the result → Assertion verifies it.

```
